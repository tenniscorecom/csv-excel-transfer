# csv-excel-transfer 仕様書

## 処理フロー

1. `[CSV] WEST` と `EAST` を `CSV(read_only=True)` で読み、`Table.concat()` で
   縦に連結してから `Table.index()` で「お客様ID」の重複を検査する。西と東で
   列が違えば `concat()` が先に `TableError` で止める。
2. `[EXCEL] INPUT_NAME` の `Sheet1`（見出し1行目）を `Excel.read_computed_rows_as_dicts()` で読む。
3. 実ヘッダーと `TRANSFER_MAPPING` の列名から `Transfer` を作る。
4. `Transfer.matched_rows()` で各 Excel 行の「業務用ID」と CSV の「お客様ID」を
   突き合する。一致した行だけ `[TRANSFER_MAPPING]` に従って更新し、
   不一致行はそのまま出力する。
5. `Excel` で出力先へ新しいブックを書き出す。
6. `READ_PASSWORD` / `WRITE_PASSWORD` のいずれかが設定されていれば、
   `ExcelCOMHandler.save_as()` でパスワード付きで保存し直す。
7. 成功時だけ入力3ファイルを削除する。

キー列、シート、見出し行は業務固定値であり config には置かない。
旧 `WEST_CSV` / `EAST_CSV` / `INPUT_XLSX`、SKIP 設定は使用しない。
`READ_PASSWORD` / `WRITE_PASSWORD` は `ExcelCOMHandler.save_as()` へ渡し、
両方空欄なら openpyxl だけで保存する。値はログへ出さない。

## Transfer API

`Transfer(read_table, write_table, mapping, read_key=..., write_key=...)` を作り、
`matched_rows()` で `(read_row, write_row)` を順に受け取り、
`transfer.apply_mapping(read_row, write_row)` で mapping に従って書き換える。
`continue` した行は apply_mapping を呼ばないため、write_table の初期値のまま残る。
最終結果は `transfer.result()` で取り出す。

```python
transfer = Transfer(read_table, write_table, configured_mapping,
                    read_key=CSV_KEY_COLUMN, write_key=EXCEL_KEY_COLUMN)
for read_row, write_row in transfer.matched_rows():
    transfer.apply_mapping(read_row, write_row)
result_table = transfer.result()
```

CSV と Excel のキーは別名（`お客様ID` ↔ `業務用ID`）なので、`read_key` と
`write_key` をそれぞれ明示する。mapping は「転記元（CSV）の列名 → 転記先（Excel）の
列名」の dict。

ファイル内のキー重複（旧 `CsvReader.index` の「踏んで上書き」）は採用しない。
`Table.concat()` で連結してから `Table.index()` を呼ぶので、ファイル内・ファイル間
を区別せず `TableDuplicateKeyError` で停止する。

## パスワード保存

`Excel`（openpyxl）はパスワードを扱えないため、`READ_PASSWORD` または
`WRITE_PASSWORD` のいずれかが指定された場合だけ、出力ファイルを
`ExcelCOMHandler` で開き直して `save_as(path, read_pw, write_pw)` で別名保存する。
両方空欄なら openpyxl だけで完結し、Excel COM は起動しない。

## 異常系

空 CSV、空 Excel、必要列不足、西/東 CSV のキー重複は例外で停止する。
CSV のキー重複（ファイル内・ファイル間とも）は `TableDuplicateKeyError`、
列名の不一致は `TableError`、CSV 関連は `ComkenError`、
Excel の列名は `ExcelColumnNotFoundError` / `TransferSourceColumnNotFoundError`、
Transfer のマッピング不備は `TransferMappingError`。
入力3ファイルの指定重複、および出力先と入力ファイルの衝突も処理開始前に停止する。
保存前の例外では入力を削除しない。dry-run では保存も削除も行わない。

`run()` は出力 `Path` を返す。転記件数は `logger.info` でログへ出す。

## 既知の制約

公開 Transfer API は転記先の `Sheet1` を新しい表として作る。このため値と列は保持するが、
入力ブックのセル書式、列幅、他シート、図形、グラフ等は出力へ引き継がない。

本ツールは現在の顧客転記業務量を対象とする。数十万件規模に向けたpandas導入や
専用の大規模データ処理は、実際に要件が出るまで対象外とする。
