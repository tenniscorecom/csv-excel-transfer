# csv-excel-transfer 仕様書

## 処理フロー

1. `[CSV] WEST` と `EAST` を `CsvReader` で読み、「お客様ID」の重複を検査して統合する。
2. `ExcelReader` で `[EXCEL] INPUT_NAME` の `Sheet1`（見出し1行目）を読む。
3. 実ヘッダーから全列の identity mapping を作る。
4. `Transfer` の transform で各 Excel 行の「業務用ID」を検索し、一致時だけ
   `[TRANSFER_MAPPING]` に従って更新する。不一致行はそのまま出力する。
5. `ExcelWriter` で出力を保存し、成功後だけ入力3ファイルを削除する。

キー列、シート、見出し行は業務固定値であり config には置かない。
旧 `WEST_CSV` / `EAST_CSV` / `INPUT_XLSX`、SKIP 設定は使用しない。
`READ_PASSWORD` / `WRITE_PASSWORD` は `ExcelWriter.save()` へ渡し、両方空欄なら
openpyxlだけ、どちらかを指定した場合はExcel COMで保存する。値はログへ出さない。

## 旧 `Sheet._transfer_by_mapping` との違い

旧実装は次のように、`ExcelWriter` から取得した特定の `Sheet` に対して内部メソッドを
直接呼んでいた。

```python
sheet._transfer_by_mapping(
    key_col="業務用ID",
    lookup=customer_lookup,
    mapping=mapping,
    header_row=1,
)
```

この方式は、既存Excelの行をキーで探して該当セルだけを書き換えるExcel専用処理である。
`Sheet`、キー列、lookup、見出し行という内部実装の都合が呼び出し側へ露出し、
CSV同士など別形式の転記には使えない。また、先頭が `_` の内部APIなので公開契約ではない。

現在は、入力用の `ExcelReader` と新規出力用の `ExcelWriter` を公開 `Transfer` に渡す。

```python
Transfer(
    excel_reader,
    excel_writer,
    identity_mapping,
    source_sheet="Sheet1",
    destination_sheet="Sheet1",
).run(transform)
```

このプロジェクトでは、入力Excelの各レコードが `source` として `transform` に渡される。
`source["業務用ID"]` で顧客lookupを引き、一致した場合だけ
`[TRANSFER_MAPPING]` の列を変更して `source` を返す。一致しない場合も元の `source` を
返すため、その行は内容を維持して出力される。一般の利用では `None` を返すとskip、
`Transfer.STOP` を返すと以降を停止できる。

| 観点 | 旧 `Sheet._transfer_by_mapping` | 現在の `Transfer` |
|---|---|---|
| API | `Sheet` の内部API | 公開API |
| 転記形式 | Excelへのキー照合更新専用 | CSV／Excelの4方向を同じ概念で扱う |
| 1件ごとの介入 | 事前にlookupを加工 | `transform(source)`で変更・skip・停止 |
| 出力方法 | 既存シートの該当セルだけ更新 | 転記先を表として書き出す |
| 書式・他シート | 既存ブックの一部セルだけを更新するため保持する | 新規ブックへ表を書き出すため保持しない |

## 異常系

空 CSV、空 Excel、必要列不足、CSV 内および CSV 間の重複 ID は例外で停止する。
保存前の例外では入力を削除しない。dry-run では保存も削除も行わない。

## 既知の制約

公開 Transfer API は転記先の `Sheet1` を新しい表として作る。このため値と列は保持するが、
入力ブックのセル書式、列幅、他シート、図形、グラフ等は出力へ引き継がない。
