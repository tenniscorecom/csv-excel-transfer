# 仕様書

このツールの処理仕様（保守する人向け）。コーディング規約は comken リポジトリの
`CONVENTIONS.md` に従う。

---

## 1. 目的・概要

西日本・東日本の **2つの顧客CSV** を 1つの lookup 辞書にマージし、INPUT エクセルの
「業務用ID」列をキーに顧客情報（お名前・ご住所・電話番号 等）を転記する。
転記後の最終ファイルは **「最終_ + 元のファイル名」で同じフォルダに保存**し、
保存が成功したら元の3ファイル（西CSV・東CSV・INPUT エクセル）を削除する。
パスワード付き保存（Excel がインストールされた PC でのみ動作）にも対応する。

毎日1回、業務担当者が手動で実行する。

---

## 2. 処理フロー

```
  西CSV ─┐
         ├─→ index() で {お客様ID: 行} にする ─→ 同じIDがあればエラーで停止
  東CSV ─┘                                                    ↓
                                                         マージ済み lookup
                                                              ↓
  INPUT エクセル（業務用ID） ──→ transfer_by_mapping で lookup を引く
                                                              ↓
                            （パスワードがあれば）COM で save_as → 開封パスワード付き
                            （なければ）                 openpyxl で save() のみ
                                                              ↓
                                            「最終_ + 元のファイル名」で同じフォルダに保存
                                                              ↓
                                            成功した場合に限り元3ファイルを削除
```

---

## 3. 入出力

| 種別 | 内容 | 場所 |
|---|---|---|
| 入力 | 西日本 顧客CSV | config.ini `[FILES] WEST_CSV` |
| 入力 | 東日本 顧客CSV | config.ini `[FILES] EAST_CSV` |
| 入力 | 作業対象 INPUT エクセル | config.ini `[FILES] INPUT_XLSX` |
| 出力 | 最終ファイル（パスワード有無は指定次第） | `INPUT_XLSX` と同じフォルダ |

---

## 4. 設定（config.ini）

| セクション | キー | 意味 |
|---|---|---|
| `[FILES]` | `WEST_CSV` | 西日本の顧客CSVパス |
| `[FILES]` | `EAST_CSV` | 東日本の顧客CSVパス |
| `[FILES]` | `INPUT_XLSX` | 転記対象の INPUT エクセルパス |
| `[CSV]` | `KEY_COLUMN` | CSV のキー列名（既定: お客様ID） |
| `[EXCEL]` | `SHEET` | INPUT エクセルの転記対象シート |
| `[EXCEL]` | `KEY_COLUMN` | INPUT エクセルのキー列名（既定: 業務用ID） |
| `[EXCEL]` | `HEADER_ROW` | 見出しの行番号（1以上; comken の `int_value(minimum=1)` で検証） |
| `[EXCEL]` | `OUTPUT_PREFIX` | 最終ファイル名の頭に付ける文字列（**空欄不可**; comken の `config.text()` で検証） |
| `[EXCEL]` | `PASSWORD` | 開封パスワード。**空欄なら COM を使わず openpyxl の save() だけ**で保存する |
| `[転記_MAPPING]` | （任意の列名） | 左=CSV の列名、右=INPUT エクセルの列名 |

### エンコーディングを `config.ini` に置かない理由

`CsvReader` は `encoding=Encoding.AUTO`（UTF-8 → CP932 の順で自動判定）が既定で、
日本の業務CSVはこの2つに収まることが多い。明示したい場合は `CsvReader(path, encoding=...)`
で渡す形にしてあり、config.ini を増やすメリットがないため、**あえて設定項目を増やしていない**。

## 5. 構成

```
main.py            エントリポイント（ログ初期化・config.require・エラー受け）
config.ini         設定（.gitignore。初回実行時に example から作られる）
実行.bat            起動用（ターミナルから叩く。`pause` 無し＝無人実行向け）

  run.py             処理の本体（index_files でマージ → ExcelWriter で転記保存 → delete_files で片付け）

  使い方.md         操作手順（非エンジニア向け）
  仕様書.md         この文書
  ERRORS.md         エラー対応
tests/
  conftest.py        共通 fixture（CSV / INPUT エクセルのサンプル生成）
  test_run.py       run.py のオーケストレーション全体
```

comken は共有サーバーを直接参照する（`実行.bat` が起動時に `PYTHONPATH` を設定）。

## 6. 実行方法

- 通常: ターミナルで `実行.bat` を叩く（または `python main.py`）
- RPA 基盤から: `実行.bat` を絶対パスで起動する（終了コードで成否を判断する）か、`python <絶対パス>\main.py` を直接呼ぶ
- 動作確認: `main.py` の `with dry_run():` を外してから実行するとそのまま動くか、`python smoke_test.py` で一時フォルダに閉じた動作確認ができる

## 7. 設計判断

### 7.1 西CSV と 東CSV を 1つの辞書にマージする

`comken.toolbox.csv.index_files([west, east], キー列名)` で `{キー: 行}` を返し、
マージ済みの辞書を返す。同じキー（お客様ID）が両方にあったら
**`CsvRowDuplicateKeyError`** で停止する（comken の index_files が直接投げる）。

- **黙って後勝ちにすると**、西と東のどちらが採用されたかログから追えず、結果が静かにブレる
- 業務ルールとして「西が正」「東が正」「住所で分ける」のいずれも決まっていない以上、
  **「どちらか分からないまま流す」よりも止めるほうが安全** という判断
- comken のメッセージには **重複した ID と、出現ファイル数** が添えられ、
  1件ずつ手で直す作業に戻れるようにしている

将来「住所で西と東のどちらを見るか切り替える」要件が出る可能性があるが、**今は作らない**。
上の重複チェックがあれば、その要件が現実になった瞬間に「既存データで重複がある」
と実行時に気づける。重複が無い前提で運用できているなら、新しい切り替えロジックを
素直に追加できる（西を優先／東を優先／住所ベース のいずれも実装しやすい）。

### 7.2 転記は列名ベース（`transfer_by_mapping`）で行う

`Sheet.transfer_by_mapping(key_col=..., lookup=..., mapping=..., header_row=...)` を使う。
列記号版（`transfer_by_letter`）ではない理由は次のとおり:

- mapping は `config.mapping("転記_MAPPING")` の戻り値をそのまま渡せる
- 入力側（CSV 列名）・出力側（Excel 列名）の両方が **設定ファイルに集約** され、
  列位置が変わってもコードを触らずに追従できる
- 列記号版は列位置が固定された帳票（雛形がセル参照で埋め込まれている等）にだけ使う

### 7.3 パスワード付き保存は COM で別途行う（openpyxl では不可能）

`openpyxl`（`ExcelWriter`）は **パスワードを保存する機能がない**。
代わりに `ExcelComHandler.save_as(path, read_pw=...)` を使う。

- **手順**: openpyxl で転記 → `f.save(path=一時ファイル)` で **出力先と同じフォルダの
  一時ファイル** へ保存 → 一時ファイルを `ExcelComHandler` で開いて
  `save_as(最終パス, read_pw=パスワード)` → 一時ファイルを削除
- **一時ファイルは try/finally で必ず消す**。COM は拡張子で形式を判断するため、
  一時ファイルの拡張子も出力先と同じにする
- **パスワードが空欄のときは COM を使わず `f.save(path=最終パス)` だけで終える**
  → Excel が入っていない環境でも動かせる
- パスワード値はログに出さない（comken の `save_as` 実装も秘匿値を出さない規約）
- **COM に到達した時点で Excel が無い PC は `ExcelApplicationNotAvailableError` で止まる**。
  それは想定どおり（COM が起動できない以上、ここで失敗するのが正解）

**`OUTPUT_PREFIX` を空欄にできない理由**

出力パスは `OUTPUT_PREFIX + INPUT_XLSX のファイル名` で組み立てるため、空欄にすると
出力パスが INPUT エクセル自身になる。転記後に元ファイルを削除する処理で、保存した
成果物まで消えてしまうため、comken の `config.text()` が空欄（前後の空白のみを含む）
を `ConfigInvalidValueError` で停止する。

この1か所で止めれば十分: `config.text()` が空白のみの入力も空とみなして弾くため、
**`Path.resolve()` での突き合わせ**は不要（成立しえない）。

### 7.4 元ファイルは「最終ファイル保存が成功した後」にだけ消す

転記中に例外が出ると元ファイルは消さない（消えていると再実行できなくなる）。
失敗時は `[EXCEL] PASSWORD` の誤りや、CSV と INPUT の列名不一致など、
  **データ起因の原因** がほとんどなので、元ファイルが残っているほうが原因調査が楽。

`comken.core.delete_files` を使う（`shutil` 直書きはしない）。
comken 側で **dry-run 対応**・**INFO ログ**・**欠損時の挙動** が揃っているため。

**保存直後の「実在確認」は comken の `ExcelWriter.save()` に任せる**

openpyxl と Excel COM（`DisplayAlerts=False`）は保存に失敗しても例外を投げない
ことがある。comken の `ExcelWriter.save()` は保存後にファイルの実在を確かめ、
無ければ `ExcelSaveNotCompletedError` で停止する。ツール側で二重にチェックしない。

**削除の部分失敗は「残ったパスを全部並べる」**

`comken.core.delete_files` は 3 ファイルを順に消して、失敗したものを `.remaining`
に集めて `FileDeletionError` で報告する。消せたものは消す方針（最終ファイルは
保存済み）としつつ、部分成功でもバッチは失敗扱いとする。古いCSV が次回実行で
拾われるのを防ぐため、ロールバックしない。

### 7.5 設定の読み取りは `comken.config` を `src/run.py` から直接呼ぶ

設定の読み取りは `comken.config` を `src/run.py` から直接呼ぶ。`config.ini` を
型付きで読む API（`config.FILES.*` / `config.EXCEL.*` / `config.CSV.*` /
`config.int_value()` / `config.text()` / `config.mapping()`）は comken 側で
提供されているので、`src/run.py` が `config.FILES.WEST_CSV` などを直接読む。

`main.py` の `config.require(...)` はそのまま — 必須項目をまとめて報告する
ための起動時チェックで、型変換はしない。型検証は `src/run.py` 側で
`config.int_value()` / `config.text()` を呼ぶ時点で行う。

- `[EXCEL] HEADER_ROW` の検証は `config.int_value("EXCEL.HEADER_ROW", minimum=1)`
  経由。整数以外または1未満なら `ConfigInvalidValueError` を送出する
  （comken 側で型・範囲を検証し、既定値へ黙って戻さない）
- `[EXCEL] OUTPUT_PREFIX` の検証は `config.text("EXCEL.OUTPUT_PREFIX")` 経由。
  空欄（前後の空白のみを含む）は `ConfigInvalidValueError` で停止する
- `[転記_MAPPING]` は **セクション名が決まっている（`**_MAPPING`）** ので、
  `config.mapping("転記_MAPPING")` の戻り値を `src/run.py` が直接 `transfer_by_mapping`
  に渡す。`config.require()` の `"SECTION.KEY"` 形式では書けないので、
  `main.py` で別途セクション存在と中身が空でないことを確かめる

### 7.6 DRY_RUN 経路の確認

`main.py` の入口で `with dry_run():` を有効にすると、
`ExcelWriter.save()` / `ExcelComHandler.save_as()` / `delete_file()` は
すべて **ログを出すだけで実際には何もしない**。DRY-RUN で本実行した smoke test で
「ファイルが1つも作られず・1つも消えず、ログに予定が出る」ことを確認済み。

本番で実行するときは `main.py` の `with dry_run():` / `with debug():` を外す。
「動かして確かめたい部分だけ局所的に dry-run にしたい」ときは、
`from comken.runtime import dry_run` を読み、その場で
`with dry_run(False):` を書く。

### 7.7 INPUT エクセルは .xlsx 形式を前提とする（既知の制限）

このツールは `openpyxl`（`ExcelWriter`）で INPUT エクセルを開き、転記後に
そのまま保存する。**`.xlsx` 形式のみ** を扱う前提になっている。

- **マクロ付きブック（`.xlsm`・`.xltm` 等）は開けない**。`openpyxl` がマクロを保持できないため、
  保存した時点で VBA が消える
- **図形・グラフ・条件付き書式・データ入力規則 等の一部は openpyxl で保持されない場合がある**
  （ライブラリが読み飛ばすか、保存時に警告なく消える）
- **「名前を付けて保存」ダイアログで選ばれた拡張子で扱う前提**なので、
  `[EXCEL] INPUT_XLSX` には `.xlsx` ファイルのパスを指定する

これが問題になる要件（`.xlsm` のマクロを残したい等）が来たら、
パスワード付き経路と同様に「openpyxl はそのまま使うが、最終保存だけ COM に置き換える」
層を足す必要がある。今は `.xlsx` のみで要件が成立しているため、**あえて制約を緩めていない**
（緩めると「動いてはいるがマクロだけ消えている」という静かな事故が起きる）。
